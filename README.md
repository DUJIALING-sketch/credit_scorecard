# 个人信贷申请评分卡建模

基于 Kaggle「Give Me Some Credit」数据集（15 万条样本），从数据清洗、特征工程、分箱、变量筛选到逻辑回归评分卡，完整实现一张申请评分卡（A 卡），并搭建 LightGBM / XGBoost 挑战者模型进行对比。另用 SQL 对清洗规则做了复核，并练习了风控常用的贷后分析方法。

## 项目文件

| 文件 | 内容 |
| --- | --- |
| `my_scorecard.ipynb` | 评分卡主流程：EDA → 清洗 → 衍生变量 → 分箱 / WOE / IV → 变量筛选 → 逻辑回归 → 评分转换 → 模型评估 → 挑战者模型 |
| `sql/risk_sql.sql` | SQL 部分：用 SQL 实现清洗规则并复核数据问题；FPD、M 阶段、Vintage、迁徙率、KS 表等贷后分析练习 |

## 数据

- 来源：[Kaggle - Give Me Some Credit](https://www.kaggle.com/c/GiveMeSomeCredit)
- 按 Kaggle 竞赛规则，本仓库**不包含数据文件**。如需运行，请下载 `cs-training.csv` 放到 `data/` 文件夹下。
- 标签 `SeriousDlqin2yrs`：两年内是否出现 90 天以上逾期。整体坏账率 6.68%。

## 主要结果

### 评分卡

| 指标 | 训练集 | 验证集 | 测试集 |
| --- | --- | --- | --- |
| AUC | 0.857 | 0.857 | 0.856 |
| KS | 0.559 | 0.563 | 0.555 |

- 入模 7 个变量，系数符号全部为正，p 值均 < 0.0001。
- 评分转换：PDO = 50，好坏比 20:1 时为 600 分。
- 训练集与测试集 KS 相差 0.4 个百分点，模型稳定。
- 业务应用：按 15% 拒绝率定出 545 分拒绝线，可拦截 63.5% 的坏客户，通过客群坏账率由 6.68% 降至 2.87%。

### 挑战者模型（测试集）

| 模型 | AUC | KS | 训练 / 测试 KS 差距 | 15% 拒绝率下拦截坏客户 |
| --- | --- | --- | --- | --- |
| 评分卡 | 0.856 | 0.555 | 0.4pp | 63.5% |
| LightGBM | 0.866 | 0.575 | 2.4pp | 65.7% |
| XGBoost | 0.866 | 0.574 | 2.1pp | 65.9% |

树模型在相同拒绝率下多拦截约 2.2 个百分点的坏客户，但稳定性和可解释性不如评分卡。银行场景倾向评分卡；互联网消金可考虑树模型，前提是做跨时间验证并用 SHAP 解释。

## 数据清洗中的发现

1. **逾期字段 96 / 98 是特殊编码**：共 269 人，三个逾期字段同时异常，坏账率 54.6%。置空并保留标记，分箱时单独作为 Missing 箱。
2. **负债比字段含义不一致**：收入缺失客户的 debt_ratio 中位数为 1,159，有收入客户为 0.30，前者存的是负债金额而非比例。收入缺失时将 debt_ratio 置空。
3. **收入缺失并非随机**：收入缺失客户坏账率 5.6%，低于整体的 6.7%，因此保留缺失作为单独信息，而不是填补。

### SQL 复核中新发现的问题（待在模型中改进）

用 SQL 分组复核清洗规则时，发现原版本的两处截断处理会误伤低风险客户：

| 问题 | 影响人数 | 该客群坏账率 | 原处理 | 改进方案 |
| --- | --- | --- | --- | --- |
| util > 10 多为数据错误 | 241 | 7.1%（接近平均） | 截断到 1.1，落入最高风险箱 | 置空 + 异常标记 |
| 收入为 0 或 1 时 debt_ratio 存的是金额 | 2,239 | 3.7%（低风险） | 截断到 5，落入最高负债箱 | 置空 + 低收入标记 |

此外，用 toad 对手写分箱交叉验证时发现：强制单调会压平 U 型关系（如 re_loans 的 IV 从约 0.06 降至 0.006 被筛除），每箱至少 5% 的限制会让低频强信号（如 dpd60）无法切分。

## 局限

- 数据没有时间字段，只能随机切分训练 / 验证 / 测试集，**无法做跨时间验证（OOT）**，PSI 也只能做形式上的检查。
- 拒绝线是在测试集上确定的，规范做法应在验证集定线、测试集确认。
- 逾期字段记录的应是申请前的历史逾期，但缺少时间戳，无法完全排除标签泄露，实际工作中需核对取数口径。
- `sql/risk_sql.sql` 中的 Vintage、迁徙率等贷后分析使用的是**模拟数据**，仅用于练习方法，不代表真实业务结论。

## 运行环境

Python 3.12；pandas、numpy、scikit-learn、statsmodels、lightgbm、xgboost、matplotlib、toad。SQL 部分使用 DuckDB。
