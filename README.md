# 个人信贷申请评分卡建模

基于 Kaggle「Give Me Some Credit」数据集（15 万条样本），从数据清洗、特征工程、分箱、变量筛选到逻辑回归评分卡，完整实现一张申请评分卡（A 卡），并搭建 LightGBM / XGBoost 挑战者模型进行对比。另用 SQL 对清洗规则做了复核，根据复核发现迭代改进了模型，并练习了风控常用的贷后分析方法。

## 项目文件

| 文件 | 内容 |
| --- | --- |
| `my_scorecard.ipynb` | 评分卡主流程：EDA → 清洗 → 衍生变量 → 分箱 / WOE / IV → 变量筛选 → 逻辑回归 → 评分转换 → 模型评估 → 挑战者模型；附正则化实验和 toad 交叉验证 |
| `sql/risk_sql.sql` | SQL 部分：用 SQL 实现清洗规则并复核数据问题；FPD、M 阶段、Vintage、迁徙率、KS 表等贷后分析练习 |

## 数据

- 来源：[Kaggle - Give Me Some Credit](https://www.kaggle.com/c/GiveMeSomeCredit)
- 按 Kaggle 竞赛规则，本仓库**不包含数据文件**。如需运行，请下载 `cs-training.csv` 放到 `data/` 文件夹下。
- 标签 `SeriousDlqin2yrs`：两年内是否出现 90 天以上逾期。整体坏账率 6.68%。

## 方法概要

- **分箱**：决策树分箱（最多 6 箱、每箱至少 5%），缺失值单独成箱，强制单调。
- **变量筛选**：从 20 个候选变量出发，依次通过 IV（≥ 0.02）、WOE 相关性（≤ 0.7）、LightGBM 重要性、VIF、系数符号与显著性（P < 0.05）检验，最终入模 7 个变量。
- **评分转换**：PDO = 50，好坏比 20:1 时为 600 分。

## 主要结果

### 评分卡

| 指标 | 训练集 | 验证集 | 测试集 |
| --- | --- | --- | --- |
| AUC | 0.857 | 0.857 | 0.856 |
| KS | 0.559 | 0.564 | 0.558 |

- 入模变量：dpd_severity、util、dpd90、age、debt_ratio、income、monthly_debt。系数全部为正，P 值均 < 0.001。
- 训练集与测试集 KS 仅差 0.14 个百分点，模型稳定。
- 业务应用：按 15% 拒绝率定出约 546 分的拒绝线，可拦截 63.4% 的坏客户，通过客群坏账率由 6.68% 降至 2.87%。

### 挑战者模型（使用相同候选变量，验证集早停）

| 模型 | 训练集 AUC | 测试集 AUC | 训练集 KS | 测试集 KS | 训练 / 测试 KS 差距 |
| --- | --- | --- | --- | --- | --- |
| 评分卡 | 0.857 | 0.856 | 0.559 | 0.558 | 0.14pp |
| LightGBM | 0.882 | 0.866 | 0.604 | 0.575 | 2.91pp |
| XGBoost | 0.878 | 0.866 | 0.598 | 0.578 | 2.03pp |

树模型测试集 AUC 高约 0.01、KS 高约 2 个百分点，但训练 / 测试差距是评分卡的 15 到 20 倍，稳定性和可解释性不如评分卡。银行场景倾向评分卡；互联网消金可考虑树模型，前提是做跨时间验证并用 SHAP 解释。

## 数据清洗中的发现

1. **逾期字段 96 / 98 是特殊编码**：共 269 人，三个逾期字段同时异常，坏账率 54.6%。置空并保留标记，分箱时单独作为 Missing 箱。
2. **负债比字段含义不一致**：收入缺失客户的 debt_ratio 中位数为 1,159，有收入客户为 0.30，前者存的是负债金额而非比例。
3. **收入缺失并非随机**：收入缺失客户坏账率 5.6%，低于整体的 6.7%，因此保留缺失作为单独信息，而不是填补。

## 迭代改进：SQL 复核发现的问题

第一版模型完成后，用 SQL 按分组复核清洗规则，发现原来的两处截断处理会把低风险客户误放进最高风险箱：

| 问题 | 影响人数 | 该客群坏账率 | 原处理 | 改进后 |
| --- | --- | --- | --- | --- |
| util > 10 多为数据错误 | 241 | 7.1%（接近平均） | 截断到 1.1，落入最高风险箱 | 置空 + `util_abnormal` 标记 |
| 收入为 0 或 1 时，debt_ratio 存的也是金额 | 2,239 | 3.7%（低风险） | 截断到 5，落入最高负债箱 | 置空 + `income_low` 标记 |

改进后重新建模：

| 指标 | 第一版 | 改进后 |
| --- | --- | --- |
| debt_ratio 的 IV | 0.071 | **0.087**（+23%） |
| 测试集 AUC / KS | 0.856 / 0.555 | 0.856 / 0.558 |
| 训练 / 测试 KS 差距 | 0.37pp | 0.14pp |
| 15% 拒绝率下拦截坏客户 | 63.5% | 63.4% |
| 收入为 0 或 1 的客户被拒比例 | — | 9.6%（低于整体 15%） |

受影响客户只占 1.65%，整体指标变化很小，这一点符合预期。改进的价值主要在于：受影响客户的风险判断更准确，debt_ratio 的含义更清晰。

重新建模时还发现，变量筛选流程缺少显著性检验：清洗修正后，income_per_person 的系数由负转正，通过了符号检验，但 P 值为 0.66。因此在筛选循环中加入了 P 值检验，将其剔除。

## 其他实验

- **toad 交叉验证**：用 toad 按相同参数分箱，无缺失值、本身单调的变量 IV 与手写版完全一致。差异来自分箱规则：强制单调会压平 U 型关系（如 re_loans 的 IV 从约 0.06 降至 0.006 被筛除）；每箱至少 5% 的限制会让低频强信号无法切分（如 dpd60）。
- **正则化实验**：sklearn 逻辑回归 C 从 1.0 降到 0.01，验证集 AUC 基本不变；样本量大、变量少，模型没有过拟合。强变量的系数几乎不受影响，弱变量和信息重复的变量被压缩得最多。

## 局限

- 数据没有时间字段，只能随机切分训练 / 验证 / 测试集，**无法做跨时间验证（OOT）**，PSI 也只能做形式上的检查。
- 拒绝线是在测试集上确定的，规范做法应在验证集定线、测试集确认。
- 逾期字段记录的应是申请前的历史逾期，但缺少时间戳，无法完全排除标签泄露，实际工作中需核对取数口径。
- 只做了一次随机切分，0.001 量级的 AUC 差异不足以说明模型显著变好。
- `sql/risk_sql.sql` 中的 Vintage、迁徙率等贷后分析使用的是**模拟数据**，仅用于练习方法，不代表真实业务结论。

## 运行环境

Python 3.12；pandas、numpy、scikit-learn、statsmodels、lightgbm、xgboost、matplotlib、toad。SQL 部分使用 DuckDB。
